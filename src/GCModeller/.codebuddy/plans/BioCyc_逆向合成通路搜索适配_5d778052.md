## 产品概述

将已完成的代谢网络逆向合成通路搜索工具，接入 BioCyc（EcoCyc）数据库：从 PGDB 的 compounds / reactions 数据中自动装配出搜索所需的「广义反应规则集 + 底盘内源代谢物汇集合」，使工具可直接以任意次级代谢产物为目标，反推出从底盘内源前体到该产物的生物合成通路，并输出带热力学、酶可得性、路径长度评分的正向合成步骤。

## 核心特性

- **数据库装配**：加载 BioCyc 工作目录，自动读取化合物与反应，构建搜索所需的规则库与汇集合，构造完成即可直接查询。
- **规则自动抽取**：把 BioCyc 中记录的具体酶反应实例，转换为带原子映射的广义反应规则（反应中心 + 相邻环境），使规则可作用于含有相同反应中心的新底物，而不仅限于已知反应。
- **底盘汇集合（可配置）**：默认采用核心中心代谢子集（枢纽代谢物 + 中心代谢白名单 + 辅因子），可切换为全库模式（全部有结构的化合物，查询时自动排除目标自身）。
- **通路搜索与评分**：以目标分子为起点反向分解，直到全部前体落入汇集合，再正向组装为生物合成顺序的步骤列表，并按热力学、酶可得性、路径长度给出全局评分与排序。
- **次级代谢产物实测**：以大肠杆菌库中多个重要次级代谢产物（铁载体、信号分子、多胺、海藻糖、群体感应分子、分支点前体）为靶标执行搜索，输出每个目标的路径条数、步数、评分与逐步反应。
- **可用性与可观测**：构造与搜索过程输出化合物/规则/汇的规模统计与耗时；对金属配位、超大、无结构、立体化学等不可处理条目自动跳过并给出计数说明。

## 技术栈

- 语言与平台：VB.NET（.NET 10，`Option Strict/Explicit/Infer On`），沿用现有工程，无新增第三方依赖。
- 算法核心：复用 `analysis\MetabolicRouter\RetroPath.vbproj`（`Netwalk` + `Chem` 分子/模式/规则引擎 + `Search` 束搜索与评分）。
- 数据源：复用 `models\BioCyc\BioCyc.vbproj` 的 `Workspace / compounds / reactions` 读取层。
- 适配层：`models\RouterAdapter\RouterAdapter.vbproj`（已同时引用 RetroPath 与 BioCyc）。
- 测试宿主：`models\BioCyc\test\test.vbproj`（Exe，已引用 RouterAdapter）。

## 实现思路

整体策略是「**一次装配，多次查询**」：在 `BioCycAdapter` 构造期完成 SMILES 净化、反应规则挖掘与汇集合构建，之后每次 `FindPathway` 只是对已装配的 `Netwalk` 发起搜索。

三条关键技术决策：

1. **SMILES 净化前置**：RetroPath 的 `SmilesIO.Parse` 只支持元素/支链/环数字/`- = #`/电价/多组分，遇到 `@`、`@@`、`/`、`\`、`%nn `会直接抛异常，元素表仅含 `Cl Br Si C N O S P F I B H`。BioCyc 的 SMILES 恰为 Kekulé 大写式但普遍带立体标记（如 `[C@@H]`、`C(\C=C/…)`），因此必须先剔除立体符号、再按元素白名单与结构上限过滤（如 `PROTOHEME` 的 `[Fe-2]` 被剔除），最后用 `Try/Catch` 包裹解析保证单条坏数据不影响整库装配。
2. **MCS 原子映射 + 反应中心提取**：BioCyc 的 `reactions` 是具体反应实例，而规则必须是带类号的 SMARTS/SMIRKS。按 readme_alg.md §2 的三步流程：把反应两侧的多组分拼成两个分子图 → 做元素/电荷一致且键级保守的最大公共子图映射（带节点预算，超预算取当前最优，属"随时算法"）→ 未映射原子 + 键级改变/断键成键的原子即反应中心 → 扩展一层邻居作为泛化环境 → 映射原子共用类号、新原子分配新类号 → 生成 `[元素(+/-):类号]` 加显式键符的模式串。**不加 Hn/Dn 约束**以保留底物混杂性，价态由 `RuleEngine` 的价态闸门兜底。
3. **辅因子以"入汇"方式处理**：`Netwalk` 的货币分子集合是硬编码的（O/CO₂/N/S/Pi），无法外部注入；改为把 NAD/ATP/CoA/ACP/SAM 等辅因子直接放进汇集合——它们在底盘中确实内源存在，逆向生成时即刻终止分支，等价于货币语义，从而**避免修改算法核心文件**。

**性能与规模**：EcoCyc 29.0 约 7588 个化合物（6264 有 SMILES）、约 2717 条反应。规则挖掘是构造期一次性开销，用「参与者重原子数上限（默认 60）+ MCS 节点预算 + 模式原子数上限（默认 24）」三重闸门控制；搜索期最大的开销是 `BeamSearch` 对上千条规则逐条双向匹配，因此规则去重（按两侧模式文本）与元素多重集预过滤是必须的，并建议首次实测采用较小的 `BeamWidth/MaxDepth`。

## 执行要点

- **必须做的防护**：所有 `SmilesIO.Parse`、`PatternMatcher.ParsePattern`、`New Rule(...)` 调用都要 `Try/Catch`；任何一条脏数据只跳过并计数，绝不让构造过程整体失败。
- **方向归正**：不要直接读 `reactions.left/right`，改用只读属性 `rxn.equation`（它已按 `REACTION-DIRECTION` 把 RIGHT-TO-LEFT / PHYSIOL-RIGHT-TO-LEFT 归正为 Reactants/Products）。
- **排序确定性**：规则与汇集合按 `uniqueId` 排序后再装入，保证同一数据库每次装配结果一致（束搜索依赖确定性顺序）。
- **命名与调试信息**：规则 `Id` 用反应 `uniqueId`，`Name` 优先 `commonName` → `systematicName` → `uniqueId`，便于把搜索结果直接回溯到 EcoCyc 反应条目。
- **爆炸半径控制**：不改动 `Netwalk.vb`、`BeamSearch.vb`、`RuleEngine.vb` 等算法核心；新增逻辑全部集中在 `models\RouterAdapter` 下的新文件；`BioCycAdapter` 的必填签名 `New(biocyc, opts, w)` 保持不变，新开关一律为可选参数且默认值等价于当前行为。
- **构造期日志**：用 `Console.Error.WriteLine`（与 `Netwalk` 现有风格一致）输出"读入化合物数/可用结构数/参与规则挖掘的反应数/生成规则数/跳过原因计数/汇大小/装配耗时"。

## 架构设计

```mermaid
flowchart LR
    A[Workspace.Open<br/>F:\ecoli\29.0] --> B[compounds<br/>7588 条]
    A --> C[reactions<br/>约 2717 条]
    B --> D[BioCycSmiles<br/>净化 + 元素白名单 + 安全解析]
    D --> E[id → SMILES 字典<br/>id → Molecule 字典]
    C --> F[AtomMapping<br/>MCS 原子映射 + 反应中心]
    E --> F
    F --> G[BioCycRuleMiner<br/>1 层邻居泛化 + SMARTS 生成 + 去重]
    G --> H[List(Of Rule)]
    E --> I[BioCycSink<br/>核心子集 / 全库模式]
    I --> J[List(Of (id, smiles))]
    H --> K[Netwalk]
    J --> K
    K --> L[FindPathway(targetSmiles)<br/>→ PathReport]
```

- **BioCycSmiles**：纯函数层，负责把 BioCyc 原始 SMILES 变成 RetroPath 可解析的 SMILES。
- **AtomMapping**：负责"原子映射 + 反应中心识别"（readme_alg.md §2.1、§2.2）。
- **BioCycRuleMiner**：负责"规则泛化与编码"（§2.3），产出 `Rule`。
- **BioCycSink**：负责底盘内源代谢物集合的两种定义模式。
- **BioCycAdapter**：编排以上四者，装配 `Netwalk`，对外只暴露 `FindPathway`。

## 实施注意与已知边界

- 化学计量数（如 3 × DHB-Ser → enterobactin）在现有规则模型中无法表达，映射时按每种参与者一个副本处理，结果可能只还原出部分单元——属已知近似，需在测试报告中如实说明。
- 立体化学与芳香性不建模：净化阶段统一剔除 `@ / \ /` 等标记，同一分子的不同立体/互变异构写法可能得到不同指纹。
- MCS 为启发式：对高度对称或超大分子（如 menaquinone-8、enterobactin）可能映射不佳或触发预算上限，此时该反应被跳过并计入统计。
- 辅因子以"入汇"近似替代真正的货币分子机制；若后续需要精确语义，再考虑给 `Netwalk` 增加可注入的 currency 参数（本次不改核心文件）。
