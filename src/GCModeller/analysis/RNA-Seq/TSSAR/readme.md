# TSSAR 算法实现原理深度解读
这篇文献（Amman et al., BMC Bioinformatics 2014）的核心贡献是把 dRNA-seq 数据中人工主观的 TSS 注释过程，转化为一个有坚实统计基础的自动化流程。下面按"要解决什么问题 → 统计模型 → 算法流程 → 工程架构"的顺序解读。
---
## 一、算法要解决的核心问题
dRNA-seq 技术用 **TEX（terminator exonuclease）** 处理 RNA 样本：
- **加工型 RNA**（5' 单磷酸）被 TEX 降解 → 在 [-] 文库中存在，[+] 文库中被去除
- **初级转录本**（5' 三磷酸）不受 TEX 影响 → 在 [+] 文库中相对富集
理想情况下，TSS 位置在 [+] 文库中 read 起始显著富集。但实际有两个困难：
1. **TEX 降解不完全**：[+] 文库仍混有加工转录本（该数据中 TSS 位置的中位富集仅约 3.5 倍），信号是**定量的**而非"有或无"的；
2. **表达水平差异巨大**：高表达区域中偶然的 read 起始堆积，可能与低表达区域的真实 TSS 信号强度相当。
因此，一个**全局固定的差异阈值（difference cutoff）或比值阈值（quotient cutoff）注定失败**——这就是 TSSAR 引入动态局部统计模型的原因。
---
## 二、统计模型（三层递进）
### 1. 基础层：Poisson 分布建模 read 起始
在转录活跃区域内，某基因组位置 read 起始计数 $Y$ 服从 Poisson 分布：
$$P(Y=k)=\frac{\lambda^k e^{-\lambda}}{k!}$$
参数 $\lambda$ 由该区域的局部表达强度（转录率 × RNA 稳定性）决定。
### 2. 比较层：Skellam 分布（两个 Poisson 之差）
TSS 判定的本质是比较 [+] 与 [-] 两个文库在同一位置的计数差。**两个独立 Poisson 变量之差服从 Skellam 分布**：
$$F(D,\lambda_{[+]},\lambda_{[-]})=\sum_{d=-\infty}^{D}e^{-(\lambda_{[+]}+\lambda_{[-]})}\left(\frac{\lambda_{[+]}}{\lambda_{[-]}}\right)^{k/2}I_{|k|}\left(2\sqrt{\lambda_{[+]}\lambda_{[-]}}\right)$$
其中 $I_{|k|}$ 是第一类修正 Bessel 函数。这样就可以计算：**在背景模型（[-] 文库）下，观察到当前 [+]/[-] 计数差的概率（p 值）**。
- $\hat{d}_i$ 异常**偏正** → 候选 TSS（初级转录本富集）
- $\hat{d}_i$ 异常**偏负** → 可能是 RNA 加工位点（[+] 文库被降解）
### 3. 修正层：零膨胀 Poisson 回归估计 λ
直接用窗口内所有计数估计 λ 会有系统偏差：基因组大部分位置**根本不转录**（结构零，structural zeros），而转录区域内的零是采样零（sampling zeros）。混合后 λ 被严重低估，导致低表达区域出现大量假阳性 TSS。
TSSAR 用**零膨胀 Poisson 回归**（zero-inflated Poisson，R 包 VGAM，全最大似然估计）分离两种零：
$$P(Y=0)=\phi+(1-\phi)\cdot e^{-\lambda}$$
- $\phi$：观察到的零是结构零的概率
- 只用**采样零和有 read 的位置**估计 λ → λ 只反映转录活跃区域的真实表达水平
这个设计巧妙之处：移除结构零后 λ 变大，**天然避免了在低 read 数区域把噪声误判为 TSS**。

## 三、算法流程（滑动窗口 + 五步计算）
### Step 0：滑动窗口设定
- 默认窗口 **1000 nt**（约等于原核基因平均长度），步长为窗口的 1/10（100 nt）
- 每个位置会在 **10 个不同的局部上下文**中被评估——平衡"窗口要足够大以稳定估计参数"与"窗口要足够小以保持局部均质性"这对矛盾
### Step 1：Winsorize 缩尾（鲁棒化）
将窗口内最高计数替换为第二高计数，最低计数同理。目的是抵抗错配 read、rRNA 等超高丰度片段造成的离群值。
### Step 2：零膨胀 Poisson 回归（每个文库独立进行）
- 用 VGAM 包对 [+]、[-] 文库分别拟合，估计 $\phi$
- **若 MLE 不收敛则丢弃该窗口**——这其实是一个内置的合理性检查：数据违反 Poisson 假设（如低复杂度文库 + 大量 PCR 重复）会被自动排除。评估数据集中仅约 0.5% 基因组（主要是 tRNA/rRNA 位点）无法建模
- 把 $\phi$ 换算成期望的结构零个数；由于两个文库面对同一基因组，未转录比例应相近，故**取两文库结构零数的平均值**并从各自计数中移除
- 剩余计数的算术平均即 $\lambda_{[+]}$、$\lambda_{[-]}$
### Step 3：文库间归一化
$$\hat{p}_i = p_i\cdot\sqrt{\bar{M}/\bar{P}}\ (\text{若}\ \bar{M}>\bar{P}),\qquad \hat{m}_i = m_i\cdot\sqrt{\bar{P}/\bar{M}}\ (\text{若}\ \bar{P}>\bar{M})$$
其中 $\bar{P}$、$\bar{M}$ 是 [+]、[-] 文库 read 起始总数。效果是把较大文库缩放到与较小文库同规模，**避免人工膨胀样本方差**（平方根形式与 Poisson 方差稳定化变换相关）。
### Step 4：Skellam 显著性计算与 p 值整合
- 计算每个位置的归一化差 $\hat{d}_i=\hat{p}_i-\hat{m}_i$
- 用 Skellam 分布计算 $P(\geq \hat{d}_i)$
- 由于每个位置被 10 个重叠窗口覆盖，取 **10 个 p 值的几何平均**作为该位置的最终 p 值
### Step 5：双阈值判定
位置被报告为 TSS 需同时满足：
1. 几何平均 p 值 < 用户设定 cutoff（范围可调 $10^{-15} \sim 0.9$）
2. **noise cutoff**：该位置在 [+] 文库中的原始 read 起始数 ≥ 阈值（默认 3）
noise cutoff 的必要性：Skellam 分布只刻画期望值之差。若 [-] 文库期望很高而 [+] 期望极小，Skellam 期望为负，可能把**根本没有 [+] read 支持的位置**判为"显著富集"——噪声阈值挡住了这类伪 TSS。
### Step 6：后处理（Web 服务端）
- **合并连续 TSS** 并聚类到最显著位置
- 按基因组上下文分类：Primary（上游 250 nt 内）、Internal（基因内）、Antisense（Ai / Ad，下游 30 nt 内）、Orphan
- 推断 Primary TSS 的 5'UTR 长度分布、评估 TEX 处理效率

## 四、工程实现架构
| 组件 | 技术 | 功能 |
|---|---|---|
| Java 客户端 | Picard tools + XZ 压缩 + Apache HttpComponents | **本地**从 SAM/BAM/BED 提取每位置 read 起始计数，避免上传 GB 级比对文件 |
| Web 服务 | Perl Dancer 框架，RESTful 架构 | 接收压缩数据、执行统计计算、可视化与后处理 |
| Standalone 版 | Perl + R | 面向高通量流水线集成（SAM 输入 → BED 输出） |
统计核心（R 的 VGAM）与前端解耦，未来可替换为非 Poisson 模型而不影响客户端和 Web 界面。

## 五、算法设计的关键洞察（为什么有效）
1. **动态 vs 静态阈值**：评估显示 TSSAR 的 F-measure 约为差值法/比值法的 **2 倍**，且 F-measure 随 p 值 cutoff 变化平缓——结果对阈值选择不敏感，而固定阈值法的最优 cutoff 随实验深度剧烈变化、无法先验确定。
2. **客观可复现**：完全不使用基因注释或启动子预测信息，避免了人工注释"只找已知基因附近 TSS"的偏倚；在 74 个实验验证的 H. pylori TSS 上，sensitive 参数精确恢复 39 个（53%），specific 参数恢复 37 个。
3. **跨物种泛化**：在与 TSSpredator 的比较中（后者在评估数据集上训练过参数），TSSAR 在全新物种 *S. maltophilia* 上用默认参数仍更优——预测 TSS 的启动子 motif 富集率 27.1% vs 18.7%，F-measure 0.46 vs 0.39（TSSpredator 多预测了约 1100 个 TSS，多为假阳性）。
**一句话总结**：TSSAR = 滑动窗口内的零膨胀 Poisson 背景估计 + Skellam 分布显著性检验 + 双重阈值过滤，把"局部表达水平自适应的统计检验"取代了"全基因组一刀切的经验阈值"，这是其性能优势的根本来源。
