# 从一个基因组到一整个群落：GCModeller 泛基因组分析模块的算法原理与实践

> 本文面向生物信息学用户，系统介绍 GCModeller 泛基因组分析模块（`PanGenome.vbproj`）的需求背景、常规分析流程、算法与统计计算原理，并通过一个完整的 R# 脚本示例，手把手带你跑通从蛋白序列聚类到十几张结果表格输出的全流程。

---

## 一、为什么我们需要泛基因组：单一参考基因组是一份"不完整的菜单"

想象你走进一家连锁餐厅，前台只给你一张"标准菜单"——招牌菜、主食、饮料，一应俱全。但任何一家常客都知道，真正的美味往往藏在不写在菜单上的"隐藏菜单"里：这家分店独家的季节限定、只有老饕才知道的秘制做法、隔壁城市分店早就下架的传奇菜品。

微生物世界正是这样一家庞大的连锁餐厅。

过去二十年的基因组学研究中，我们习惯为每一个物种挑选一个"参考基因组"（reference genome），把它当作这个物种的标准菜单。但微生物群落分析的实践一次次提醒我们：**同一物种的不同菌株之间，基因组差异可以大到令人咋舌**。大肠杆菌的泛基因组几乎是无底洞——每测序一个新菌株，几乎都能发现一批前所未见的基因。这些差异不是测序噪音，而是一个物种真正的"活法"：

- **核心基因组（core genome）**：所有菌株都有的基因，好比连锁店的招牌菜——当家管家基因、DNA 复制机器、核糖体，少了它们任何一家分店都开不下去；
- **附属基因组（accessory genome）**：只有部分菌株携带的基因，就像各家分店的隐藏菜单——耐药基因、毒力因子、特殊代谢通路，往往通过水平基因转移（HGT）像"外卖骑手"一样在菌株之间穿梭传递。

在微生物群落分析（比如肠道菌群、土壤微生物组、临床病原菌群体）中，只盯着一份参考基因组，会让我们犯下"看菜单点菜"的错误：真正决定某株菌能不能在小肠道里安家、能不能扛住抗生素轰炸的，恰恰是那些写在隐藏菜单上的附属基因。

泛基因组（pan-genome）分析正是为此而生：**它不问"这个物种的基因组长什么样"，而问"这个物种的全部基因组池里，到底有哪些基因，每个基因在多大比例的菌株中出现"**。它把成百上千个二进制的"有/无"信号，压缩成一张可以读出进化故事的地图。

## 二、微生物群落泛基因组分析的常规流程

一套典型的泛基因组分析，无论用什么工具实现，都大致遵循同一条流水线：

```
基因组注释 ──► 基因家族聚类 ──► PAV/CNV 矩阵 ──► 家族分类 ──► 下游统计与进化分析
```

1. **基因组注释**：对群落中每个菌株的基因组做基因预测与注释，得到每个基因组的基因列表及其在染色体上的位置（通常是 GFF3 格式）。这一步相当于把每家分店的菜品登记造册。

2. **基因家族聚类**：把所有基因组预测出的蛋白序列拿来做相似性聚类，把"同一道菜的不同分店版本"归为一族——这就是**基因家族（gene family）**，也叫直系同源组（orthologous group）。常规做法有两条路线：
   - **两两比对路线**：全基因组之间做 BLAST，提取双向最佳命中（BBH，Bidirectional Best Hit），再通过并查集传递合并；
   - **一步聚类路线**：直接用 cd-hit 这类快速序列聚类工具，以一条阈值（如 60% 一致度）把所有蛋白序列一次性分成若干簇。

3. **构建 PAV/CNV 矩阵**：对每个基因家族，统计它在每个基因组中的拷贝数——存在记 1（或多拷贝），缺失记 0。这就是**存在/缺失变异矩阵（PAV，Presence/Absence Variation）**，它是泛基因组分析的"中央账本"。

4. **基因家族分类**：根据每个家族在基因组池中的出现比例，将其划分为核心（core）、软核心（soft-core）、壳（shell）、云（cloud）四大类——这套"云壳核"的术语体系最初由 Tettelin 等人在 2005 年的泛基因组开山之作中提出。

5. **下游统计与进化分析**：包括泛基因组积累曲线（估计这个"菜单"还有多少隐藏菜品没被发现）、基因组间遗传距离、共线性区块与结构变异检测、信息熵与降维可视化等——这也是 GCModeller 模块最出彩的部分。

GCModeller 的泛基因组模块把上述五步全部实现为一个高度优化的 VB.NET 分析器 `GenomeAnalyzer`，并同时兼容 BBH 比对路线与 cd-hit 聚类路线。下面我们深入它的算法内核。

## 三、模块的分析方法原理：一场精心编排的"后厨流水线"

打开 `GenomeAnalyzer.vb`，主分析函数 `RunAnalysis` 就是一张清晰的后厨工序单：

```vb
''' <summary>
''' 家族聚类完成之后的所有分析步骤
''' </summary>
Private Function RunAnalysis(orthologDict As Dictionary(Of String, BiDirectionalBesthit())) As PanGenomeResult
    ' ...
    ' 步骤 1+2: PAV 矩阵构建与基因家族分类（并行）
    Call BuildPAVAndClassify(F, N)
    ' 步骤 3: 遗传距离矩阵
    ' 步骤 4: 共线性分析
    ' 步骤 5: 结构变异检测
    ' 步骤 6: 泛基因组曲线计算
    ' 步骤 7: 统计汇总（基因组统计、PCA、基因组熵）
    ' 步骤 8: SV结构变异的信息熵与聚类分析
End Function
```

在此之前还有一道前置工序：把外部传入的直系同源分组（cd-hit 簇或 BBH 配对）通过并查集合并成基因家族。我们按流水线顺序，一道一道工序拆开来看。

### 3.1 前置工序：并查集——"朋友圈"的传递性合并

基因家族聚类的本质是一个**传递闭包**问题：A 和 B 是同源，B 和 C 是同源，那么 A、B、C 应该归入同一家族——哪怕 A 和 C 从未直接比较过。这就像朋友圈的合并：你朋友的朋友，也是你的朋友。

`GenomeAnalyzer` 用经典的**并查集（Union-Find）**数据结构（`Models/UnionFind.vb`）来维护这套朋友圈关系。它有两个精心打磨的实现细节值得一提：

- **迭代式路径压缩**：`Find` 操作采用两趟迭代把沿途节点直接挂到根上，刻意不用递归——因为在百万级基因的规模下，一条很长的合并链可能把递归栈压垮；
- **k−1 次合并**：一个含 k 个基因的 cd-hit 簇，只需要 k−1 次 `Union` 就能全部归并，而不必先展开成 O(k²) 个两两配对关系。在一个几百基因组的数据集上，这个差别是"上亿个中间对象"和"线性扫描"的差别。

更讲究的是带来源的合并重载 `UnionRange(genes, sources)`：**只有来源（replicon 编号）不同的基因之间才合并**，同一基因组内部的旁系同源拷贝不会被错误地捏合成一个家族。这相当于规定"同一家分店自己的菜不算连锁品牌菜品"。

### 3.2 步骤 0：索引化——给百万基因发放"索书号"

在真正的分析开始之前，`BuildIndex` 会做一件看似枯燥、实则决定性能上限的事情：把所有字符串主键（基因 ID、基因组名、家族 ID）一次性映射为连续的整数下标，后续所有热循环都在整数并行数组上进行。

```vb
''' <summary>
''' 一次性构建好所有的整数索引，后续的分析过程将不再需要针对上百万个基因
''' 反复做字符串哈希查找
''' </summary>
Private Sub BuildIndex()
    geneIds = New String(n - 1) {}
    geneIndex = New Dictionary(Of String, Integer)(n)
    geneGenome = New Integer(n - 1) {}
    ' ... 同时把每个基因组内的基因按（染色体，起始位点）排序，只排一次供所有算法复用
End Sub
```

这就好比图书馆不会每次借书都翻遍书架，而是先给每本书编好索书号——之后所有的检索、排序、统计都只在数字层面进行。模块的源码注释里把这个设计总结为三条军规：**索引化、去二次化、并行化**。泛基因组曲线从 O(迭代数 × 基因组数 × 家族数) 的全表扫描降到 O(迭代数 × 基因数) 的增量计数、共线性分析不再对每个基因组对做全基因表扫描，都受益于此。

### 3.3 步骤 1+2：PAV 矩阵与"云壳核"四分类——基因家族的性格测试

`BuildPAVAndClassify` 是整条流水线的核心：它并行地遍历每个基因家族，统计它在 N 个基因组中的拷贝数，然后当场完成分类：

```vb
Dim ratio As Double = presence / N

If ratio = coreThreshold Then          ' 100%：核心基因
    isCore(k) = True
    category = CategoryCore
ElseIf ratio >= softCore AndAlso ratio < coreThreshold Then   ' ≥95%：软核心
    isSoftCore(k) = True
    category = CategorySoftCore
ElseIf ratio >= shell AndAlso ratio < softCore Then           ' 15%~95%：壳基因
    isShell(k) = True
    category = CategoryShell
Else
    isCloud(k) = True               ' <15%：云基因
    category = CategoryCloud
End If
```

四个类别的阈值默认为：核心 `CoreThreshold = 1.0`（100% 存在）、软核心 `SoftCoreThreshold = 0.95`、壳基因下限 `ShellThreshold = 0.15`，其余归入云基因。用餐厅的语言来说：

- **核心基因**是招牌菜，每家分店必有；
- **软核心基因**是几乎人人都点的热销菜，偶尔有个别分店不供应；
- **壳基因**是区域限定菜，一半分店有、一半分店没有；
- **云基因**则是流传在坊间的传闻菜品——只有不到 15% 的分店听说过它。

此外模块还顺带标记了几个有用的衍生属性：**特有基因**（只在一个基因组中出现，`presence = 1`）、**附属基因**（非核心，`presence < N`）、**单拷贝直系同源家族**（在所有基因组中都恰好存在一份）——后者是后续构建进化距离的"金标准"材料。

值得一提的是，每个家族的 PAV 行都会补齐全部基因组键（缺失的填 0 而不是留空），这是为了让 R# 脚本导出表格时不会把"该基因组没有此基因"误读成 `NA`——一个小小的工程细节，却避免了很多下游统计的暗坑。

### 3.4 步骤 3：基因组间的遗传距离——两种"量菜尺"

模块提供了两把尺子来度量基因组两两之间的差异：

**尺子一：Jaccard 距离（位图加速版）。** 当没有比对信息（cd-hit 聚类路线）时，`CalculatePanGenomeJaccardDistance` 把每个基因组的家族集合编码成二进制位图（bitmap），两个基因组的交集大小通过位图的 AND 运算加 popcount 在 O(家族数/64) 内得到：

```vb
For w As Integer = 0 To words - 1
    intersectionCount += BitOperations.PopCount(a(w) And b(w))
Next
' |A ∪ B| = |A| + |B| - |A ∩ B|
Dim unionCount As Integer = sizes(i) + sizes(j) - intersectionCount
jaccardDistance = 1.0 - (CDbl(intersectionCount) / CDbl(unionCount))
```

这就像比较两个顾客的点菜单：把每道菜编号成一个二进制位，"你都点过哪些菜"一次 AND 运算就数出来了。相比逐个遍历 HashSet，快了一个数量级。

**尺子二：单拷贝直系同源平均相似度。** 当有 BBH 比对结果时，模块改用进化分析的"金标准"：只取那些在所有基因组中都恰好一份的单拷贝直系同源家族，累加每对基因组之间所有同源基因对的 `1 − 平均一致度`，再除以单拷贝家族数取平均。只挑单拷贝，是因为多拷贝家族的"哪个拷贝对应哪个拷贝"本身就是一笔糊涂账，拿来算距离会引入噪音。

### 3.5 步骤 4：共线性区块——基因组的"章节对照"

共线性（collinearity）分析回答的问题是：两个基因组是否把同一段"章节"以相同的顺序装订在染色体上？`CalculateCollinearity` 以每个基因组对为单位，找出所有 1:1 同源基因对，按染色体上的顺序排列——**顺序保持一致的一长串同源基因对，就构成一个共线性区块**。区块要求至少 `MinCollinearGenes = 5` 对基因才算数，以过滤零散的巧合。

模块会为每个区块记录两端的基因组/染色体、逐基因配对信息（基因组数量超过 32 对时自动只保留统计摘要以省内存），以及区块在两个基因组上覆盖的起止坐标——这些坐标可以直接用于绘制共线性点图和带状图。

### 3.6 步骤 5：结构变异检测——找出菜单上被改动过的菜

基于 PAV/CNV 和共线性结果，`DetectStructuralVariations` 把每一条"菜单被改过"的证据登记为一条结构变异（SV）记录，主要类型包括：

| SV 类型 | 判定逻辑 | 通俗解读 |
|---|---|---|
| `PAV_Absence` | 该家族在过半基因组中存在（"潜在核心"），但某个基因组中缺失 | 连锁店的招牌菜，这家分店居然没有 |
| `PAV_Presence` | 该家族只出现在不超过 2 个基因组中 | 全 brand 只有这一两家分店的秘传菜 |
| `CNV_Gain` | 拷贝数 ≥ 中位拷贝数 × 2 且 > 1（`CNV_Gain_Factor = 2.0`） | 这家分店把这道菜的分量翻了好几倍 |
| `CNV_Loss` | 中位拷贝数 > 1 且拷贝数 ≤ 中位数 × 0.5（`CNV_Loss_Factor = 0.5`） | 这家分店把这道菜减量供应 |
| `Collinearity_Break` | 共线性区块两端染色体不同（易位） | 整章内容被装订到了另一本书里 |

每个 SV 事件都会记录涉及的基因组、家族、相关基因列表、拷贝数与中位数，并按家族顺序分配可复现的 `SV_ID` 编号（如 `SV_1`、`SV_2`）——这份 SV 清单正是后面第 4 节"双熵分析"的原始食材。

### 3.7 步骤 6：泛基因组曲线——"这个菜单还有多大？"

泛基因组积累曲线（pangenome accumulation curve）回答一个经典问题：**随着不断加入新的基因组，泛基因组（新菜品的发现速度）和核心基因组（始终保留的菜品）分别如何变化？** 如果泛基因组曲线持续上扬，说明这个物种的基因池深不见底（开放型泛基因组，open pan-genome）；如果趋于平缓，说明菜单基本摸清了（封闭型，closed）。

朴素的算法是：每次随机打乱基因组加入顺序，每加一个基因组就把全部家族扫一遍统计"出现过几次"。`GenomeAnalyzer.CalculatePangenomeCurve` 做了两处优化：

- **蒙特卡洛洗牌**：预先用固定种子生成 100 次随机排列（`CurveIterations = 100`），既保证并行模拟的结果可复现，又像"洗 100 次牌取平均"一样消除单次顺序的偶然性；
- **增量计数**：为每次迭代维护一个家族计数器，加入第 i 个基因组时只更新该基因组携带的家族——计数从 0 变 1 的家族就是新发现的泛基因组成员；计数恰好等于当前步数的家族就是"至今全勤"的核心基因；计数加一后达到 `ceil(软核心阈值 × 当前基因组数)` 的家族仍算软核心：

```vb
Dim softCeil As Integer = Math.Min(CInt(Math.Ceiling(softCore * ([step] + 1))), [step] + 1)

For Each famIdx As Integer In fams
    Dim c As Integer = cnt(famIdx)
    If c = 0 Then pan += 1          ' 新菜品！泛基因组 +1
    If c = [step] Then core += 1    ' 之前每家分店都有，依然是核心
    If (c + 1) >= softCeil Then soft += 1  ' 出现比例仍达软核心阈值
    cnt(famIdx) = c + 1
Next
```

复杂度从 O(迭代数 × 基因组数 × 家族数) 降到 O(迭代数 × 基因总数)。源码注释还解释了一个容易被问到的现象：核心基因的判定（100% 全勤）非常苛刻，基因组越加核心曲线衰减越快，而软核心曲线（默认 95%）则能保持在一个可观的水平上。

## 四、统计计算原理：把海量 0/1 矩阵压成有故事的数字

分析器跑完之后，结果对象 `PanGenomeResult` 里已经积累了 PAV 矩阵、SV 清单、共线性区块、积累曲线等一大批中间产物。模块的统计层（步骤 7、8）再从中提炼出几组高度浓缩的数字。这一步的哲学，就是把一张巨大的二进制表格压缩成几个"每个都自带生物学故事"的连续值。

### 4.1 基因组的香农信息熵：这个基因组的"混搭程度"有多高？

模块为每个基因组计算一个基于 PAV 矩阵的香农信息熵（`entropy.md` 中讨论的第一种口径）：设泛基因组共有 N 个基因家族，某基因组存在 K 个、缺失 N−K 个，则

$$H = -\big(p\ln p + (1-p)\ln(1-p)\big), \quad p = K/N$$

实现于 `BuildGenomeEntropyData`，并对边界做了短路保护（K 为 0 或 K 等于 N 时直接取 0，避免对数炸出 NaN）。

这个熵该怎么理解？把它想象成**"惊讶程度"的计量器**：如果每个基因组都几乎全勤（p 接近 1），那么"某基因组缺一道菜"这件事毫无悬念，熵接近 0；反过来，如果一个基因组的存在/缺失比例接近五五开——比如通过大量水平基因转移囤了一堆别的菌株都没有的附属基因——那么随便翻开它的基因清单，你都会频繁地"惊讶"，熵就高。

因此这个熵是**基因组可塑性的代理指标**：

- 熵值极低的基因组，往往是那些生活在稳定封闭环境中的内生菌、专性寄生菌——它们经历过大量基因丢失，菜单被精简到只剩招牌菜；
- 熵值较高的基因组，则多半来自土壤、肠道这类复杂环境，拥有庞大的隐藏菜单以应付多变的生存挑战。

实现上，presence 计数是逐 PAV 行枚举、只对拷贝数大于 0 的条目做查找的，复杂度为 O(所有家族的出现基因组数之和)，配合惰性计算加缓存（`GetGenomeEntropyData`），重复取用不会重复付费。

### 4.2 SV 双熵与 KMeans 四象限：基因家族的"性格测验"

这是整个模块最具原创性的分析（详见 `sv_entropy.md` 的设计讨论）。思路是：把 SV 清单重排成两张"家族 × 基因组"矩阵——

- **CopyNumber 矩阵**：每格是某家族在某基因组上的 SV 拷贝数；
- **Median 矩阵**：每格是该家族的 SV 中位数（家族级常量，无 SV 事件的基因组记 0）。

然后**对每一行**（即每个基因家族）分别计算香农熵，得到两个数：

- **CopyNumber 熵 $H_{cn}$**：把各基因组的拷贝数归一化为离散分布 $p_i = CN_i/\sum CN_i$，计算 $H=-\sum p_i\ln p_i$。由于拷贝数本身是小的离散整数，无需分箱。**$H_{cn}$ 高**说明该家族在不同基因组中拷贝数五花八门——扩张收缩频繁；**低**则说明剂量受到严格的纯化选择，家家户户一个剂量。
- **Median 熵 $H_{med}$**：把 Median 的精确取值（0、1、2、3……）直接当作离散类别统计频率——0（无 SV 事件）本身也是一种"结构状态"。它刻画的是**SV 状态在基因组间分布的均衡度**：结构形态处处一致还是各显神通。

把这两个熵当作 X、Y 坐标，每个基因家族就成了二维平面上的一颗星。模块（`SVDomainEntropy.vb`）随后做了三件严谨的预处理与后处理：

1. **低频过滤**：出现 SV 事件的基因组数低于 `max(1, ceil(0.05 × N))` 的家族先被剔除——绝大多数基因组里都是 0 的稀疏行算出的熵偏向 0 且易受噪音干扰，先请出场；
2. **Z-score 标准化**：两个熵序列各自减均值、除以总体标准差，防止方差大的维度在欧氏距离中一家独大；
3. **KMeans 聚类（默认 k=4，`SVClusterCount`）**：在标准化坐标上聚类，空簇剔除，簇编号按簇中心坐标排序做**确定性重排**——同样的数据重跑一遍，簇标签不会漂移。

聚类之后，模块按每个簇的均值相对全局均值的高低，自动贴上四象限的性格标签：

| 簇均值特征 | 标签 | 生物学解读 |
|---|---|---|
| $H_{cn}$ 低 + $H_{med}$ 低 | **僵化/保守型** | 核心管家基因，剂量与结构都被纯化选择死死摁住，动一下就伤筋动骨 |
| $H_{cn}$ 高 + $H_{med}$ 低 | **剂量调谐型** | SV 结构形态高度一致（如转座子驱动的串联重复），但拷贝数灵活伸缩——典型如抗性基因、P450 家族，靠"加菜不加新菜"来调节剂量 |
| $H_{cn}$ 低 + $H_{med}$ 高 | **结构微调型** | 拷贝数稳定但结构形态多变——基因融合、结构域重排的温床 |
| $H_{cn}$ 高 + $H_{med}$ 高 | **混沌/快速进化型** | 剂量和结构都在剧烈洗牌，基因组在这里像一块"试验田"，常与强正向选择或环境适应相关 |

这份输出的价值在于：它把传统 PAV 分析只关心的"有/无"，解耦成了**剂量维度的多态性**和**结构维度的多态性**两个正交的故事线，让你能判断一个家族的进化到底是被"剂量选择"主导，还是被"结构创新"主导。

### 4.3 PCA：把 PAV 矩阵投到一张"星座图"上

`BuildPCAData` 以基因组为样本、以基因家族拷贝数为特征做主成分分析，取前 3 个主成分。为了控制计算量并突出主要信号，特征家族按"家族基因总数降序"取 Top-N（默认上限 5000 个家族）。每个基因组的散点用**核心基因占比**着色——于是你在 PCA 图上往往能看到：核心占比高的基因组（保守的"老派分店"）聚在一侧，附属基因-rich 的基因组（激进的新派分店）散在另一侧。这是快速审视群体结构的第一张图。

### 4.4 类别占比的两种口径：消除"分店数量"的放大效应

`BuildCategoryPercent` 统计核心/软核心/壳/云四类基因在各个基因组中的占比，并提供了两种口径：

- **按基因数（by gene）**：该类别在基因组内的拷贝数之和 ÷ 该基因组基因总数 × 100；
- **按家族个数（by family）**：该类别出现的家族数 ÷ 该基因组内出现的家族总数 × 100。

为什么要有两种口径？源码注释讲得很清楚：当基因组数量很多时，壳基因和云基因会因"基因组数量的累加"而在绝对数量上远远超过核心基因——但它们在单个基因组内部的占比其实并不高。以"单个基因组内部的占比"来度量，就像用"人均消费"而不是"全店总流水"来衡量一家分店的经营结构，消除了分店数量的放大效应。由于四个类别构成完整划分，两套口径下四类占比之和都约为 100%。

## 五、实战：用 R# 跑通整个泛基因组分析流程

理论讲完，现在进厨房。下面以官方示例脚本 `cdhit_family.R` 为蓝本，逐步讲解如何通过 R# 语言驱动这个模块。脚本场景是：手上有一批微生物群落的基因组注释和蛋白序列，希望做基于基因家族的泛基因组分析。

所有 API 由 `comparative_toolkit` 程序包中的 `pangenome` 模块暴露（对应源码 `R#/comparative_toolkit/pangenome.vb`）。

### 5.1 准备食材：读入序列并做 cd-hit 家族聚类

```r
require(GCModeller);
require(jsonlite);

imports "bioseq.fasta" from "seqtoolkit";
imports "kmers" from "seqtoolkit";
imports "pangenome" from "comparative_toolkit";

let dir as string = ?"--dir" || stop("no analysis data provided!");
let family_json = file.path(dir, "cdhit-family.json");
let family_result = {
    if (file.exists(family_json)) {
        # use cache
        jsonlite::fromJSON(family_json, what = "cdhit-family");
    } else {
        let proteins = read.fasta(file.path(dir, "proteins.faa"));
        let cache_data = cdhit_clusters(proteins, identities = 0.6);

        writeLines(jsonlite::toJSON(cache_data$clusters), con = family_json);
        cache_data$clusters;
    }
};
```

`read.fasta` 读入全部蛋白序列，`cdhit_clusters(identities = 0.6)` 以 60% 序列一致度为阈值做一步式聚类——每个簇就是一个候选基因家族。这里还展示了工程上的好习惯：聚类结果缓存为 json，第二次运行直接读缓存，避免重复计费。

### 5.2 备菜：构建分析上下文

```r
let orth = multiple_genome_alignment(family_groups(family_result));
let geneset = read_genetable(file.path(dir, "genes.csv"));
let context = build_context(geneset, soft_core_threshold = 0.8,
                            genome_size = c(2000, 8000), uniqueByAcc = TRUE);
```

这一小段做了四件事：

- `family_groups` 把 cd-hit 簇整理为"家族 → 成员基因"的分组结构；`multiple_genome_alignment` 再将其整理为多基因组比对形式；
- `read_genetable` 读入基因注释表 `genes.csv`（每行一个基因：GeneID、所属基因组、染色体、起止坐标），它就是 `GenomeAnalyzer` 构造函数接收的 `GeneTable` 数据；
- `build_context` 创建分析上下文（内部构造 `GenomeAnalyzer` 实例），几个参数值得注意：
  - `soft_core_threshold = 0.8`：把软核心阈值调低到 80%（默认 0.95），在基因组数量不多的小型群落中，95% 的全勤率太苛刻，软核心曲线会迅速归零；
  - `genome_size = c(2000, 8000)`：按基因数量过滤基因组——基因数少于 2000 或多于 8000 的基因组（往往是组装质量差的碎片或污染）被请出分析；
  - `uniqueByAcc = TRUE`：按 accession ID 对基因去重，防止同一基因因注释重复而被计入两份拷贝。

### 5.3 开火：执行分析并打包结果

```r
let result = pangenome::analysis(context, orth);

writeBin(result, con = file.path(dir, "result.zip"));
result = readBin(con = file.path(dir, "result.zip"), what = "pangenome");
```

一行 `analysis` 触发第 3 节描述的整条流水线：PAV 四分类 → 遗传距离 → 共线性 → SV 检测 → 蒙特卡洛曲线 → 统计汇总 → SV 双熵聚类。随后 `writeBin` 把整个结果对象序列化打包成 `result.zip`——像把一整桌菜打包成外卖——再 `readBin` 读回。这个"打包再拆包"的小仪式在 R# 中有一个实际的好处：结果对象经过一次完整的序列化往返，后续在脚本任何位置取用都等价于从磁盘加载，方便断点续跑。

### 5.4 出餐：导出结果表格与 HTML 报告

最后是丰收时刻——脚本一口气导出了 **13 类 csv 表格**和一份交互式 HTML 报告：

```r
let scatter = pangenome::scatter_set(result);

write.csv(as.data.frame(scatter$stats),   file = file.path(dir, "genome_stats.csv"));
write.csv(as.data.frame(scatter$pca),     file = file.path(dir, "pav_pca.csv"));
write.csv(as.data.frame(scatter$entropy), file = file.path(dir, "pav_entropy.csv"));

write.csv(genetic_distance(result), file = file.path(dir, "genetic_distance.csv"));
write.csv(pav_matrix(result),       file = file.path(dir, "pav_matrix.csv"));
write.csv(curve_data(result),       file = file.path(dir, "pangenome_curve.csv"));
write.csv(sv_table(result),         file = file.path(dir, "sv_table.csv"));
write.csv(pav_table(result),        file = file.path(dir, "pav_table.csv"));

# SV structural variation matrices: rows are gene families, columns are genomes
write.csv(sv_copy_number_matrix(result), file = file.path(dir, "sv_copy_number_matrix.csv"));
write.csv(sv_median_matrix(result),      file = file.path(dir, "sv_median_matrix.csv"));

# gene family distribution percent matrix, by two calibers:
# "gene" = copy number based, "family" = family count based
write.csv(category_percent_matrix(result, by = "gene"),   file = file.path(dir, "category_percent_gene.csv"));
write.csv(category_percent_matrix(result, by = "family"), file = file.path(dir, "category_percent_family.csv"));

# SV information entropy scatter data with the kmeans clustering result
write.csv(as.data.frame(sv_entropy(result)), file = file.path(dir, "sv_entropy.csv"));

writeLines(report_html(result), con = file.path(dir, "result.html"));
```

下面这张"菜单解读卡"逐一说清每张表格里都装了什么。所有列名均与源码中 `stats_frame`、`pca_frame`、`entropy_frame`、`sv_entropy_frame`、`sv_table`、`pav_table`、`GetPAVMatrix`、`GetSVMatrix`、`GetCategoryPercentMatrix` 等导出函数的实现一一对应。

## 六、13 类结果表格内容详解

### 6.1 基因组三件套：`genome_stats.csv`、`pav_pca.csv`、`pav_entropy.csv`

三张表都以基因组为行，从不同角度给每个基因组画"侧写"。

**`genome_stats.csv`**（`scatter_set(result)$stats`，`stats_frame` 导出）——每个基因组的"基本档案"：

| 列名 | 含义 |
|---|---|
| `gene_count` | 该基因组的基因总数 |
| `specific_count` | 该基因组独有的特异基因家族数量（全群落只此一家） |
| `core_ratio` | 核心基因占比(%)：该基因组内出现的核心家族数 ÷ 基因总数 × 100 |

**`pav_pca.csv`**（`scatter$pca`，`pca_frame` 导出）——第 4.3 节那张"星座图"的原始数据：

| 列名 | 含义 |
|---|---|
| `pc1` / `pc2` / `pc3` | 前三个主成分的得分坐标 |
| `core_ratio` | 核心基因占比(%)，可作散点着色维度 |
| `gene_count` | 基因总数 |

（各主成分的方差贡献率形如 `PC1 (42.51%)`，以标签形式附在数据集中，参与 PCA 的家族数默认上限 5000。）

**`pav_entropy.csv`**（`scatter$entropy`，`entropy_frame` 导出）——第 4.1 节"混搭程度"计量器的读数：

| 列名 | 含义 |
|---|---|
| `entropy` | 存在/缺失均衡度香农熵（自然对数），值越高说明该基因组的存在/缺失结构越均衡、可塑性越强 |
| `present_families` | 该基因组存在的家族数 K |
| `absent_families` | 缺失的家族数 N−K |
| `specific_ratio` | 特有基因占比(%) |
| `core_ratio` | 核心基因占比(%) |
| `gene_count` | 基因总数 |

典型的读法：把 `entropy` 与 `specific_ratio` 一起看——两者双高的基因组，多半就是那个通过 HGT 囤了一堆隐藏菜单的"激进派"。

### 6.2 中央账本：`pav_matrix.csv`

行是基因家族，列是全部基因组，单元格是该家族在该基因组的拷贝数（缺失补 0）。这是整个分析最原始也最核心的矩阵——所有后续统计都能从它重建。可以拿它画 PAV 热图，一眼看出哪些家族是"全员到齐"的招牌菜、哪些是"零零散散"的坊间传闻。

### 6.3 亲缘关系：`genetic_distance.csv`

对称方阵，行列都是基因组名，单元格是两基因组间的平均遗传距离（BBH 路线为单拷贝直系同源的平均 `1−一致度`；cd-hit 路线为 Jaccard 距离）。这张表可以直接喂给层次聚类或 NJ 等建树工具，得到群落内菌株的亲缘关系树。

### 6.4 菜单扩张史：`pangenome_curve.csv`

| 列名 | 含义 |
|---|---|
| `GenomeCount` | 已加入分析的基因组数量（横轴） |
| `TotalGenes` | 泛基因组大小：至今出现过的家族总数（蒙特卡洛 100 次平均） |
| `CoreGenes` | 核心家族数：在已加入的全部基因组中都存在（100% 全勤） |
| `SoftCoreGenes` | 软核心家族数：出现比例不低于软核心阈值 |

把 `TotalGenes` 对 `GenomeCount` 作图就是泛基因组曲线：曲线仍在上扬 → 开放型泛基因组，这个物种的隐藏菜单还远没有摸完；`CoreGenes` 曲线快速衰减属正常现象（100% 全勤的标准很苛刻），对照 `SoftCoreGenes` 曲线看更有参考价值。

### 6.5 变异清单：`sv_table.csv` 与 `pav_table.csv`

**`sv_table.csv`**（`sv_table(result)` 导出）——第 3.6 节 SV 检测的明细账，行名为 `SV_ID`（如 `SV_1`）：

| 列名 | 含义 |
|---|---|
| `Type` | 变异类型：`PAV_Absence` / `PAV_Presence` / `CNV_Gain` / `CNV_Loss` / `Collinearity_Break` |
| `GenomeName` | 发生变异的基因组 |
| `FamilyID` | 关联的基因家族 |
| `ClusterSize` | 涉及的基因数量 |
| `RelatedGenes` | 涉及的基因 ID 列表（分号连接） |
| `Category` | 所属家族类别（Core/SoftCore/Shell/Cloud 等） |
| `Dispensable` | 是否附属基因家族 |
| `SingleCopyOrtholog` | 是否单拷贝直系同源 |
| `CopyNumber` | 变异发生时的拷贝数 |
| `Median` | 该家族在有 SV 基因组中的中位拷贝数 |
| `Description` | 自然语言描述 |

**`pav_table.csv`**（`pav_table(result)` 导出）——每个基因家族一行的"家族档案"：

| 列名 | 含义 |
|---|---|
| `cluster_genes` | 家族内全部成员基因 ID（分号连接） |
| `size` | 家族成员基因数 |
| `category` | 家族类别 |
| `dispensable` | 是否附属家族 |
| `singlecopy_ortholog` | 是否单拷贝直系同源 |
| 各基因组名列（动态） | 该家族在各基因组中的拷贝数 |

两张表是下游筛选的工作台：比如"列出所有发生在核心家族上的 `PAV_Absence` 事件"——这类事件最值得深挖，因为一个近乎全员的招牌菜在某家分店消失，背后往往有强选择的影子。

### 6.6 SV 原始矩阵：`sv_copy_number_matrix.csv` 与 `sv_median_matrix.csv`

两张表都是"行 = 存在 SV 事件的基因家族（按家族 ID 排序），列 = 全部基因组"的矩阵，单元格分别是 SV 拷贝数和 SV 中位数，无事件的格子记 0。它们是第 4.2 节双熵计算的直接输入；保留这两张原始矩阵，也让你可以在 R# 里用自己的方式重新分箱、重新定义熵，甚至接入其他聚类算法。

### 6.7 类别占比：`category_percent_gene.csv` 与 `category_percent_family.csv`

两张表结构相同：行是各基因组（外加最后一行 `average` 全基因组平均值），列是四个家族类别（核心 / 软核心 / 壳 / 云），单元格是百分比。区别在于口径：

- **`category_percent_gene.csv`**（`by = "gene"`）：按基因拷贝数计——"这家分店的厨房里，四类菜各占多少 Cook 位"；
- **`category_percent_family.csv`**（`by = "family"`）：按家族个数计——"这家分店的菜单上，四类菜各占多少页"。

每行四列之和约为 100%。对比两种口径，可以识别"家族数量很多但单基因组内拷贝占比不高"的壳/云基因膨胀现象（第 4.4 节）。

### 6.8 性格测验成绩单：`sv_entropy.csv`

行名是基因家族 ID，这是第 4.2 节双熵 + KMeans 分析的最终输出（`sv_entropy_frame` 导出）：

| 列名 | 含义 |
|---|---|
| `h_copy_number` | CopyNumber 熵原始值（拷贝数分布的均衡度） |
| `h_median` | Median 熵原始值（SV 状态分布的均衡度） |
| `z_copy_number` | Z-score 标准化后的 CopyNumber 熵（KMeans 实际使用的坐标） |
| `z_median` | 标准化后的 Median 熵 |
| `present_genomes` | 存在 SV 事件的基因组数量（低频家族已被过滤） |
| `cluster` | KMeans 簇编号（确定性重排，重跑不漂移） |

用 `z_copy_number` 对 `z_median` 作散点、按 `cluster` 着色，就得到那张"基因家族性格测验"的四象限散点图：左下角是摁住不动的保守派，右上角是鸡飞狗跳的试验田，其余两个象限分别讲述剂量调谐与结构微调的故事。

### 6.9 一页看懂全部：`result.html`

最后，`report_html(result)` 把上述所有统计结果编织成一份单文件交互式 HTML 报告——四类家族的饼图与条形图、泛基因组曲线、PCA 散点、PAV 热图、SV 双熵散点图尽在其中。发给合作者时，不需要对方安装任何软件，浏览器双击即可"点菜"。

## 结语

回顾整个模块的设计，你会发现一条贯穿始终的线索：**把生物学问题翻译成可计算的数学对象，再把计算结果翻译回生物学故事**。

- "哪些基因是大家共有的" → 并查集传递合并 + 出现比例四分类；
- "菜单还有多大" → 蒙特卡洛洗牌 + 增量计数的积累曲线；
- "谁和谁更像" → 位图 popcount 的 Jaccard 距离或单拷贝直系同源平均一致度；
- "哪些菌株藏着特别的故事" → 存在/缺失均衡度的香农熵；
- "哪些家族在剧烈演化、又是以什么方式演化" → SV 双熵 + KMeans 四象限。

而所有这些计算，最终都以 13 张结构清晰的 csv 表格和一份 HTML 报告交到你的手中——每一个数字都可以追溯到源码中的某一行判定逻辑，每一个散点背后都站着一个可能正在适应新环境的基因家族。这大概就是算法产品最好的样子：数学严谨得像教科书，用起来却像翻菜单一样轻松。

如果你想让这套流水线跑起来，只需要准备三样食材：蛋白序列（`proteins.faa`）、基因注释表（`genes.csv`）和一个 R# 脚本——剩下的，交给 `pangenome::analysis()`。
