## 行内公式改为 HTML 标记（当前方案）

两篇博客的行内公式已从 `$…$` 全量改写为 `<i>` / `<sub>` / `<sup>` +
Unicode 希腊字母：`$x_{im}$` → `<i>x</i><sub><i>im</i></sub>`、`$10^{-16}$` →
`10<sup>−16</sup>`、`$\max_j|ES|$` → `max<sub><i>j</i></sub> |ES|`、分数改成
`(1 + <i>λa</i><sub><i>j</i></sub>) / (1 + <i>λ</i>)`。映射表在
`blog/tools/inline_math_to_html.py`（65 + 10 条，未登记就报错）。

块级公式保持 `$$…$$` 不变；三种产物：
- `*.md`：块级 LaTeX + 行内 HTML（给能跑 MathJax 的编辑器）
- `*.images.md`：块级换成 `formulas/blog1/eqNN.png`，行内仍是 HTML（给博客站）
- `*.html`：由 `tools/build_html.py` 从 .md 直接生成（无模板），MathJax 本地优先

坑（重要）：
- GFM 表格里公式的绝对值竖线会切断单元格，必须写 `&#124;`；
  但**分隔行 `|---|---|` 没有空格**，任何"按空格识别分隔符"的正则都会把它整行转义，
  批量处理时要先 `fullmatch(r"\|[\s:|-]+\|")` 跳过分隔行。
- 行内 `<i>` 放进标题（如 `### 细节二：max<sub>j</sub> |ES| …`）可正常渲染。
- 行内图方案已废弃（`formulas/*/inline/` 不再生成），`crop_formulas.R` 现在只处理块级公式。

## 公式转透明 PNG（博客站不跑 MathJax 的兜底）

`blog/formulas/` 下 85 张透明底公式图：`blog1/eq01..eq10.png`（块级）、
`blog1/inline/inl001..inl065.png`、`blog2/inline/inl001..inl010.png`
（下篇 0 条块级公式，原文公式全在行内）。另生成 `*.images.md`：
把每处公式换成 `<img>`，块级居中限宽，行内带实测 `vertical-align`。

流水线在 `blog/tools/`（4 个脚本，可重跑）：
1. `make_formulas.py`：扫描 md（跳过代码块/行内 code）→ 生成 HTML → 无头 Chrome
   以 `--default-background-color=00000000 --force-device-scale-factor=3` 渲染
   （`vendor/mathjax-tex-svg.js`，17px 字号）→ `--dump-dom` 读回每张公式的包围盒
   与基线（零宽 inline-block 落在基线上）→ 整页透明截图。
2. `crop_formulas.R`：按 bbox 裁切 → 按 alpha 墨迹再裁 → 四周补 2px 透明（RGB 填字色，
   防缩放黑边）→ 用 `depth = 基线落差 + PAD - 底部裁掉量` 修正行内对齐。
3. `gen_images_md.py` / `make_formula_readme.py`：生成 `*.images.md` 与清单。

踩过的坑（重要）：
- MathJax 的 `getBoundingClientRect()` **小于实际墨迹**：大括号、深下标会溢出盒子，
  按 bbox 直接裁会切掉括号。必须 pad 后再按 alpha 裁（PAD_X/Y ≥ 14 CSS px）。
- 行内页要给公式两侧留 24px 的空 inline-block，否则 `右键` 的中文会混进图里。
- 替换时不能边遍历边改（倒序替换），否则块级公式会整体错位（先把 span 与图片配对，
  再逆序写回）。
- 行内公式的 `depth` 必须是 `bbox_bottom - baseline`，且要考虑裁剪与 padding 的增量，
  否则深度恒为 0、图会浮在字上方。
