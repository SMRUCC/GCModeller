BinaryMatrixHeader {SMRUCC.genomics.Analysis.HTS.DataFrame} .NET clr documentation

BinaryMatrixHeader

Description

HTS_matrix 二进制矩阵文件的头部模型，同时是全项目唯一的头部编解码实现。

之所以要把头部收敛到一个类里面：v1 的头部原先分别由 BinaryMatrix.readMatrix、 HTSMatrixReader 的构造函数以及 PLAS.NET/SGrid/ZipPersists.readBinaryMatrix 各自手写解析，三处偏移量稍有不同步就会出现"读出来全是垃圾数据"这类难以定位的问题。

格式版本：v2 使用了另一个 magic 字符串（BinaryMatrixHeader.MagicV2），而不是在原有 magic 之后插入一个版本号字段。原因是 v1 的头部紧接着 magic 的是 BinaryWriter.Write() 的 7-bit 长度前缀，旧读取器会把新的 Int32 版本号当作标签长度继续解析，最终在 JSON 反序列化处抛出难以理解的异常；换 magic 则可以让旧读取器在第一次 21 字节比较时就 立即 fail-fast。两个 magic 长度相同（21 字节），因此 BinaryMatrix.MagicHeader 常量与 Encoding.ASCII.GetBytes(BinaryMatrix.MagicHeader) 的既有用法不受影响。

v2 布局（定长整数一律小端，与 v1 的 nsamples/nfeatures 保持一致； 矩阵数据区仍然是网络字节序/大端的 double —— 这个"头部小端、负载大端"的约定必须原样保留）：

 [21]  magic  = "GCModeller/HTS_bin/v2"
 [i32] version = 2
 [i32] flags   bit0..3 codec(0=none,1=gzip,2=zlib), bit8 hasBlockIndex, bit9 featureIdsInTrailer
 [1]   dtype   (0 = double, 预留 float32)
 [3]   reserved = 0
 [i64] indexOffset  (trailer 的绝对文件偏移；-1 = 无 trailer)
 [str] tag
 [i32] nsamples
 [i32] nfeatures    (-1 = 写入方尚未落定，即文件未完成写入)
 [i32] blockRows    (压缩分块行数；0 = 不切块)
 [str] sampleIdsJson
 [str] featureIdsJson (flags.bit9 置位时写 "[]"，真实列表在 trailer)
 [data] 按块排列的行数据
 [trailer at indexOffset]
     [i64] nblocks
     [i64] blockOffsets[nblocks + 1]   (相对数据区起点，便于整个文件搬迁)
     [str] featureIdsJson              (仅 flags.bit9 置位时存在)

这样设计之后，无需回填的内容全部可以确定性算出（数据区起点、块大小、尾部位置）， 只有 BinaryMatrixHeader.Nfeatures 与 BinaryMatrixHeader.IndexOffset 两个定长字段需要在 Complete() 时 seek 回填，而这两个字段的位置在写入头部时就已经记录下来了。

# namespace SMRUCC.genomics.Analysis.HTS.DataFrame
export class BinaryMatrixHeader {
   # 块偏移表（相对 BinaryMatrixHeader.DataStart）；Nothing 表示没有索引
   BlockOffsets: integer;
   # 压缩分块的行数；0 或负数表示不切块
   BlockRows: integer;
   # 每一行的字节数
   BlockSize: integer;
   Codec: Compression;
   # 数据区起始的绝对文件偏移。由读取方根据自身流位置推算，不会写进文件
   DataStart: integer;
   # 数据区元素类型：0 = double（当前唯一支持的值）
   DataType: Byte;
   FeatureIds: string;
   FeatureIdsInTrailer: boolean;
   # 头部标志位，见 BinaryMatrixHeader.FlagHasBlockIndex 等常量
   Flags: integer;
   HasBlockIndex: boolean;
   # trailer（块索引所在位置）的绝对文件偏移；-1 表示没有 trailer
   IndexOffset: integer;
   IsCompressed: boolean;
   # 行数是否已经落定？
   IsFinalized: boolean;
   # 块数量（BinaryMatrixHeader.BlockRows 为 0 时视为单块）
   Nblocks: integer;
   # 行数（特征数）；-1 表示写入方尚未落定行数，这样的文件不完整
   Nfeatures: integer;
   # 列数（样本数）
   Nsamples: integer;
   SampleIds: string;
   tag: string;
   # 格式版本：1 = 旧格式，2 = 当前格式
   Version: integer;
}
